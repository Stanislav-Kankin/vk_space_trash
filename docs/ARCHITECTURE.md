# Architecture

## Phase 1

В `frontend/` находится автономный React-прототип. Zustand временно моделирует игровые состояния и переходы. TanStack Query установлен как граница будущего server state. VK Bridge инициализируется безопасно: локальный запуск продолжает работать, если контейнер VK недоступен.

Визуальная герметизация перехода и процедурный Web Audio в `src/audio.ts` являются только клиентской обратной связью. Состояние комнаты меняется один раз в середине анимации, а доступность перехода по-прежнему проверяет store; будущий backend не должен зависеть от длительности анимации или возможности воспроизвести звук.

Для закрытой альфы постоянный лом, улучшения, инструменты, комплект экспедиции и разведданные кораблей временно сохраняются в browser `localStorage`; активная экспедиция не сохраняется. Схема хранения версии 3 содержит прогресс каждого `shipId`, одноразовые награды завершения, прочность инструментов и до двух выбранных инструментов. Разведданные фиксируются только при успешной эвакуации, а износ инструментов сохраняется сразу после применения. Миграция сворачивает старый сканер до бинарного уровня с возвратом лома и начисляет награду уже завершившим первый корабль. Это хранилище будет удалено из роли источника прогресса после появления серверной сессии. Production frontend собирается multi-stage Dockerfile и отдаётся Nginx-контейнером через loopback-порт хоста.

## Target services

```text
VK Mini App -> Nginx -> FastAPI -> PostgreSQL
VK community -> vkbottle bot -> FastAPI
```

Frontend: React, TypeScript, Vite, VK Bridge, VKUI assets, TanStack Query, Zustand и Motion.

Backend Фазы 2: Python 3.12, FastAPI, SQLAlchemy 2, Alembic, PostgreSQL и pytest. Доменный слой будет отвечать за генерацию карты, конечный автомат экспедиции, события, бой, награды и улучшения.

## State authority

Клиент отправляет намерение пользователя вместе с idempotency key и ожидаемой версией экспедиции. Сервер блокирует строку активной экспедиции в транзакции, проверяет допустимость перехода, применяет результат и увеличивает `state_version`. Повторный ключ возвращает ранее сохранённый ответ.

## Authentication

В VK frontend передаёт исходные подписанные параметры запуска на backend. Backend проверяет подпись и свежесть, после чего выдаёт короткую игровую сессию. Локальная авторизация будет доступна только через явный `DEV_AUTH_MODE`, отключённый в production.
